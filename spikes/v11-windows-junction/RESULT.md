# V11：Windows のジャンクション

実施：2026-10-08（Windows 11、NTFS、一般ユーザー、R 4.6.1、Defender のリアルタイム保護は有効、P3M 2026-10-01）
再現：`pwsh -File run.ps1`（pwsh 7）。依存の一覧は `../v02-binary-extract/windows-deps.R` を使う。
OneDrive の同期フォルダでの確認は `pwsh -File onedrive.ps1`（run.ps1 の後に。試験用のフォルダは最後に消す）。

## 結論

**成功。** プロジェクトのライブラリに、キャッシュのパッケージへのジャンクションを置くだけで、R はすべて読み込める。管理者権限も開発者モードも要らない。Defender が有効でも、展開とリンクは十分に速い。OneDrive の同期フォルダの中でも読み込めるが、OneDrive がジャンクションに ReadOnly を付けるため、消す前にそれを外す必要がある。

## 確かめたこと

対象は tidyverse とその依存の97パッケージ（推奨パッケージを除く）。

| 項目 | 結果 |
|---|---|
| 取得（16並列） | 96 MB を 14 秒 |
| キャッシュへの展開（`<pkg>\<版>\<pkg>`） | 5.3 秒（5,094 ファイル、180 MB） |
| ジャンクション97個の作成 | 67 ミリ秒 |
| 読み込み | 97/97 が読み込めた。`installed.packages()` も97件 |
| `library(tidyverse)` の時間（3回） | ジャンクション 0.84〜0.88 秒、実体のライブラリ 0.78〜0.84 秒 |
| `find.package("dplyr")` | キャッシュの実体のパスになる（R がパスを正規化する。Linux と同じ） |
| キャッシュ内の最長の相対パス | 91 文字（置き場所の長さに足しても、MAX_PATH の 260 に収まる見込み） |
| 日本語と空白を含むパス | ジャンクションのライブラリ・キャッシュとも、読み込めた |

### 読み込み中の操作（R が dplyr の DLL を読み込んだまま）

| 操作 | 結果 |
|---|---|
| キャッシュの DLL を消す | できない（アクセス拒否） |
| ライブラリのジャンクションを消す | できる。キャッシュの実体は残る |
| ジャンクションを張り直す | できる |

### 壊れたジャンクション（リンク先のキャッシュを消した場合）

| 見え方 | 結果 |
|---|---|
| PowerShell の `Test-Path`・`Exists` | TRUE（ジャンクション自体の属性を見るため） |
| R の `file.exists()`・`dir.exists()` | TRUE |
| R の `Sys.readlink()` | 空文字（ジャンクションには使えない） |
| R の `installed.packages()`・`requireNamespace()` | 含まれない・読み込めない |
| 再帰なしの削除（`Directory.Delete(path)`） | できる |

### OneDrive の同期フォルダの中のプロジェクト

`%OneDrive%` の中に試験用のプロジェクトを作り、ライブラリに、キャッシュ（OneDrive の外）へのジャンクションを3つ置いた（cli・jsonlite・glue）。

| 経過 | ジャンクション | プロジェクトのファイル | リンク先のキャッシュのファイル | R での読み込み |
|---|---|---|---|---|
| 直後 | `Directory, ReparsePoint` | `Archive` | `Archive` | できる |
| 30 秒後〜2 分後 | `ReadOnly, Directory, ReparsePoint`（OneDrive が ReadOnly を付けた） | `Archive, ReparsePoint`（OneDrive のプレースホルダーになった） | `Archive`（変わらない） | できる |

- ジャンクションは、ReadOnly が付いた後は**そのままでは消せない**（アクセス拒否）。ReadOnly を外せば、再帰なしで消せる。リンク先のキャッシュは残る
- OneDrive がリンク先の中身をクラウドに上げたかは、この方法では分からない（リンク先のファイルの属性は変わらなかった）

## 設計への影響

1. **リンク（第9章の手段3）**：Windows では、パッケージのディレクトリへのジャンクションを使う。シンボリックリンク（開発者モードか管理者権限が要る）は使わない。ジャンクションを作るには、Windows の API を呼ぶ crate が要る
2. **壊れたリンクの検出**：存在の確認（`exists`）では分からない。リンク先の `DESCRIPTION` を読めるかで判定する（status の「ロックとライブラリ」の確認）
3. **削除**：ジャンクションは再帰なしで消す。再帰的に消すとリンク先のキャッシュを消す恐れがある（Rust の `remove_dir_all` はジャンクションをたどらないが、実装で確かめる）
4. **キャッシュの片づけ**：R が読み込んだ DLL は消せない。キャッシュから消すときは、失敗を許して次の機会に回す
5. **速度**：Defender が有効でも、キャッシュ済みの同期はジャンクションの作成だけで済む（97個で 67 ミリ秒）。初回の構築の大半は取得と展開で、V13 の Windows 分で rok として測る
6. **OneDrive**：ライブラリのジャンクションを外す・張り替えるときは、ReadOnly の属性を外してから消す（OneDrive の中のプロジェクトで同期が失敗しないように）。`.rok/library/` は Git の管理外だが、OneDrive では同期の対象になるため、OneDrive の中にプロジェクトを置く利用者への注意を文書に書く
